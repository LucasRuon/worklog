## Boundary e Landing

- `providers/github.ts` utiliza `gh api --method GET --hostname github.com` com autenticação existente, sem obter token nem registrar stderr/body bruto. Apenas repositórios cadastrados e GitHub canônico são aceitos.
- Cache SQLite aditivo, snapshots por repo/número e páginas normalizadas com ETag; reindexar não apaga snapshots. 304 preserva os dados, 401/403/offline marca stale; falha de review/check é indisponível, nunca aprovação.
- Intervalo padrão 300000 ms, backoff/rate limit respeitados mesmo em solicitação manual. Sincronização automática somente após habilitar explicitamente o repositório com POST `/api/prs/sync`; testes não iniciam acesso GitHub incidentalmente.
- `core/summaries.ts` gera português com evidências enumeradas, ruleVersion fixa e snapshot persistido. Não há API de IA. Solicitado ausente continua ausente; conclusão de ferramenta não equivale a teste aprovado.
- Retomada/verificação: estado de review/check fora do catálogo público é recurso `unavailable`, com itens vazios; preservar o PR e os outros recursos. Rejeitada a alternativa de tratar qualquer texto como estado conhecido ou descartar o PR inteiro por falha de enriquecimento.

## Checks

**C1** — Paginação de PRs preserva draft, autor/branches/datas e diferencia open, merged e closed sem merge; revisão/check desconhecidos/sem permissão permanecem indisponíveis; commits da head têm vínculo explícito sem atribuir PR a todo commit local.
Proof: `npm run test:unit -- tests/providers/github.test.ts` — `GitHub: páginas, estados e enriquecimento sem falsa aprovação`.

**C2** — ETag/304 mantém snapshots; offline/401/403/rate limit preservam cache marcado stale; nenhuma requisição ocorre antes de retryAt, mesmo force; todas as chamadas são GET e não propagam conteúdo bruto no diagnóstico.
Proof: mesmo arquivo — `GitHub: cache 304, falhas e rate limit respeitado`.

**C3** — GET `/api/prs` usa autenticação/filtros, POST `/api/prs/sync` aceita só repo UUID cadastrado, e erro do provedor aparece no estado da sincronização sem apagar histórico.
Proof: `npm run test:integration -- tests/integration/pull-requests.test.ts` — `PRs: API autenticada, escopo e snapshots persistidos`.

**C4** — Resumo distingue solicitado/realizado/verificado, aponta cada alegação verificável para evidência e não declara testes aprovados, PR mesclado ou história completa sem dados que comprovem.
Proof: `npm run test:unit -- tests/core/summaries.test.ts` — `resumo: fatos, falhas e lacunas com evidências`.

**C5** — Mesma seleção produz o mesmo texto/ruleVersion/evidenceIds; fontes/período/projetos excluídos não aparecem; snapshot mantém evidências e versão.
Proof: mesmo arquivo — `resumo: determinismo, filtros e persistência`.

## Swept

- validation: C1/C3/C5, UUIDs, canonical GitHub, status/ISO e limites; payload externo é allowlist.
- failure: C2/C4, cache e incerteza preservados; nenhum diagnóstico bruto.
- retry: C2, ETag e idempotência repo+número, sem deletes de snapshots.
- authorization: C3, auth/Host/Origin da API e credential helper gh; somente GET externo.
- concurrency: lease por repo e promise compartilhada por contexto; snapshots transacionais por rodada.
- lifecycle: snapshots e resumos persistidos, origem/IDs/versionamento; não editar eventos brutos.
- external failure: C1/C2, revisões/checks indisponíveis explicitamente.
- transitions: C1/C4, fechado não é merged; tool.completed não comprova teste.
- observability: C2/C3, sync timestamp, retryAt e código de erro seguro.
